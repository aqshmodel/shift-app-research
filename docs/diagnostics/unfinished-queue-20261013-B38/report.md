## 事実と作業状態を別々に扱う提案

事実の軸は現行の `support_status`、`value_state`、`verification_stage` と出典・留保を維持する。作業の軸では、公開資料の調査終了、回答待ち、試験待ち、再開条件付き保留を識別する。

例：「勤務規則への自然言語変換は公開確認範囲で見つからなかった。公開調査を終了し、新仕様公開時に再開する」と記録しても、製品評価unknownは変えない。「非対応」と言えるのは適用範囲を伴う明示的な非対応根拠がある時だけ。

モデル上、task_stateとsupport_statusは独立しており、unsupported/unknownのまま作業の終了を記録する設計は可能。ただし現行の広い設問をそのままdoneへ変更すると、設問全体が確認できたと誤読される。終了範囲と終了理由を保存し、未解決条件を関連付けてから、公開調査終了を表示できる管理方法を設計する。`not_applicable` を「調べても分からない」の代わりには使わない。
